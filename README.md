# 우리의 배움 숲 🌱

**소리 중심 한글·영어 학습**과 **덧셈·뺄셈·곱셈 연습**을 위한 가족용 웹앱.
태블릿(아이패드) 가로 전체화면에 맞춰 큰 그림·큰 버튼으로 구성.

공개 사이트: https://kimthegooner.github.io/kids-learn/ — 같은 주소를 공유하면 각자 브라우저에서 아이 이름을 설정할 수 있습니다.

## 설계 원칙
- **소리 우선, 글자는 보조** — 모든 화면은 큰 그림 + 자동 음성. 지시문은 음성으로.
- **한·영 병행** — 같은 그림에 "사과 / apple"을 연속으로 들려줌.
- **터치 한 번 = 소리 한 번** — 아이가 혼자 눌러도 작동.
- **세션 5~7분** — 짧게 끝나고 별 보상.

## 실행
```bash
npm install
npm run dev
# http://localhost:3000  (태블릿에선 같은 와이파이로 PC IP:3000)
```

## 화면 흐름
처음 방문하면 아이 이름 또는 별명을 입력합니다. 이름 없이 둘러볼 수도 있습니다.
홈에서 **오늘의 놀이**를 시작하거나 **한글 / 영어 / 수학**을 직접 선택합니다.

- **변신 사진관**: 꼬마 공룡, 우주 로봇, 별빛 공주, 한복, 축구 유니폼, 왕관, 토끼 귀, 선글라스까지 8가지 변신. 얼굴·몸을 따라 소품과 옷을 합성합니다. 홈의 ‘찰칵! 오늘은 내가 주인공’으로 들어갑니다. 한복 2색, 거울 반전, 사진 촬영·기기 저장을 지원합니다.

- **다양한 악기로 음악 듣기**: 홈의 상상놀이 바로 아래에서 들어갑니다. 작은 별·비행기·나비야·런던 다리 4곡과 피아노·기타·바이올린·플루트·트럼펫·색소폰·실로폰 7종을 골라 연주를 듣습니다. 악기를 1~7개 선택하면 같은 멜로디를 동시에 연주합니다. 모두 함께·피아노만 버튼, 연주 중 악기별 음량 조절, 재생·일시정지·구간 이동·처음부터·반복 재생을 지원합니다. 곡/악기 구성을 변경하면 처음부터 준비하고, 화면 이탈·백그라운드 이동 시 모든 소리를 멈춥니다. `data/songs.json`의 전래 선율을 공개 라이선스 음색 샘플로 편곡한 28개 MP3를 사용합니다.
- **악기 도감**: 기존 악기 5개를 악기 주제로 옮기고 플루트·색소폰·실로폰을 더해 8종으로 구성했습니다. 그림을 누르면 이름 다음에 악기 음색이 나오며, 한글·영어 듣기 옆의 ‘악기 듣기’로 음색만 들을 수도 있습니다. 샘플과 편집 내역은 `public/audio/instruments/credits.json`에 기록합니다.

- **오늘의 놀이**: 낱말 3개 듣기 → 같은 낱말 그림 찾기 3문제 → 한 음절 쓰기 → 완료. 기기의 날짜를 기준으로 하루에 한 번 별을 받습니다. 복습이 필요한 낱말을 우선 선택합니다.
- **한글**: 카테고리 19종 → 배우기 / 듣고 찾기 / 잇기 / 따라쓰기 / 획순쓰기.
- **듣고 찾기**: 글자를 읽지 않고 한국어 또는 영어 소리를 듣고 그림 선택. 5문제마다 별과 완료 화면. 처음에는 보기 2개, 최근 6문제 중 도움 없이 처음에 맞힌 문제가 3개면 보기 3개, 5개면 보기 4개. 한글·영어 기록은 따로 집계합니다.
- **영어**: 기존 인사·가족·감정 등의 듣고 말하기 카드 + 기초 낱말 듣고 찾기.
- **수학**: 덧셈 / 뺄셈 / 곱셈 / 섞어서 중 선택. 덧셈·뺄셈 범위는 10·20·50·100 이내, 곱셈은 2~9단 중 여러 단을 고릅니다. 기본은 20 이내 혼합 연산 + 2~5단, 직접 답 입력, 10문제입니다. 5문제도 선택 가능하며 완료 시 별 하나. 풀이 힌트는 수 분해와 곱셈 묶음을 보여줍니다.
- **따라쓰기**: 낱말을 한 음절씩 크게 표시. 초록 시작점과 옅은 획 가이드 위에 그리고, “다 썼어”를 누르면 다음 글자로 이동. 정확도나 획순을 자동 채점하지 않습니다.
- **획순쓰기**: 자음·모음의 획순 애니메이션과 자유 따라쓰기. “다 썼어”로 활동을 기록합니다.
- **부모님**: 아이 이름 변경, 최근 활동, 복습할 내용, 최근 7일 도움 없이 첫 정답 비율, 수학 단계 설정.

### 각자의 이름으로 사용하기

첫 화면이나 **부모님 → 아이 이름**에서 이름·별명(최대 16자)과 선택 사항인 영어 이름을 설정합니다. 홈 제목과 인사, 브라우저 제목, 생활 영어 자기소개, 촬영 사진 문구와 파일명에 적용됩니다. 이름을 비워 저장하면 “우리의 배움 숲”으로 표시됩니다. 공유되는 기본 페이지 제목에도 특정 아이의 이름을 넣지 않습니다.

`lib/profile.ts`가 `kidslearn.profile.v1`에 이 사이트의 브라우저별 이름을 저장합니다. 친구가 자기 브라우저에서 이름을 바꿔도 다른 사람에게 영향을 주지 않습니다. 새로고침과 같은 사이트의 다른 탭에서도 반영되며, 저장을 사용할 수 없으면 현재 실행에서 이름을 적용하고 안내합니다. 이름 변경은 기존 별과 학습 기록을 유지합니다. 한 브라우저의 표시 이름 설정이며, 아이별 학습 기록을 나누는 다중 계정 기능은 아닙니다. 기기를 바꾸거나 사이트 데이터를 삭제하면 이름을 다시 설정해야 합니다.

### 학습 기록과 난이도
`lib/progress.ts`에서 브라우저 `localStorage`에 최근 활동 500개와 오늘의 놀이 완료 날짜를 저장합니다. 기존 별 기록(`kidslearn.stars`)은 유지합니다. 로그인·서버·기기 간 동기화는 없습니다. 브라우저 데이터를 지우면 기록도 사라집니다. 저장이 차단되면 메모리에서 계속 동작하며 부모 화면에 안내합니다.

정답 기록은 **첫 시도 성공 여부와 힌트 사용**을 구분합니다. 틀린 뒤 맞힌 것을 처음부터 맞힌 것으로 집계하지 않습니다. 쓰기 완료는 아이의 “다 썼어” 선택을 의미하며 글씨 숙달도 평가가 아닙니다.

기본은 선택한 연산 범위를 유지합니다. 부모 화면에서 자동 도전을 켜면 덧셈·뺄셈 5문제를 도움 없이 연속으로 맞혔을 때 다음 범위(10 → 20 → 50 → 100)로 넓어집니다. 곱셈은 고른 구구단을 유지합니다. 이전의 수 세기 설정은 기록을 보존하면서 새 연산 기본값으로 전환됩니다.

### 음성과 터치
`lib/speech.ts`는 1,050개의 로컬 MP3를 우선 재생합니다. 낱말, 고정 안내, 자음·모음·음절과 숫자를 담았으며 수학 문제와 힌트는 녹음 조각을 순서대로 연결합니다. 이름처럼 미리 준비할 수 없는 문장은 기기의 TTS를 사용합니다. 카카오톡 등 내장 브라우저의 TTS 구현에 학습 낱말 전체가 의존하지 않도록 했습니다. 실제 카카오톡 앱/기기별 최종 검증은 별도 후속 확인 대상입니다.

음성은 한 Audio 요소를 재사용하고 버튼을 누르는 동작 안에서 즉시 재생을 요청합니다. 재생 거절은 ‘다시 재생’으로 안내하며 실패를 학습 완료로 기록하지 않습니다. 새 재생이나 화면 전환 시 이전 음성과 지연 재생을 함께 취소합니다. 음악방은 Web Audio API의 공통 시각에 모든 AudioBufferSourceNode를 예약해 합주를 동기화합니다. 재생 버튼 동작 안에서 AudioContext를 활성화하고 선택한 MP3가 모두 디코딩된 뒤 시작합니다. 악기별 GainNode와 합주 음량 여유를 적용하며, 선택 변경·대기 취소·종료 뒤 늦게 도착한 파일은 재생하지 않습니다. 참고: [MDN AudioBufferSourceNode.start](https://developer.mozilla.org/en-US/docs/Web/API/AudioBufferSourceNode/start).

`npm run prepare-speech`는 macOS의 Yuna/Daniel과 ffmpeg로 음성 파일과 `data/speech-clips.json`을 재생성합니다. `npm run prepare-instruments`, `npm run prepare-music`는 CC BY 3.0의 FluidR3 / MIDI.js 음색으로 짧은 악기 소리와 동요 음원을 만듭니다. 준비된 파일을 배포하므로 방문자는 설치나 음성 생성 API가 필요하지 않습니다.

`components/TraceCanvas.tsx`는 그린 획의 좌표를 비율로 저장해 화면 회전·크기 변경 시 다시 그립니다. 여러 손가락의 입력이 섞이지 않도록 하나의 포인터만 받습니다. 글자나 낱말을 바꾸면 새로 시작합니다.

### 카메라 변신 놀이

카메라는 사용자가 버튼을 눌러 권한을 허용해야 켜집니다. **localhost 또는 HTTPS**가 필요합니다. 태블릿에서 `http://PC의IP:3000`으로 접속한 경우 카메라를 쓸 수 없으므로 HTTPS로 접속합니다. 최신 Chrome·Safari의 카메라, Web Worker, OffscreenCanvas, ImageBitmap을 사용하며 실제 성능은 기기에 따라 다릅니다.

Google [MediaPipe Face Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/web_js)와 [Pose Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)를 별도 Worker에서 실행합니다. 동시 처리 프레임을 하나로 제한하며 얼굴은 최소 40ms, 몸은 최소 55ms 간격으로 인식을 요청합니다. 실제 인식 속도는 기기 성능에 따라 달라집니다. 화면 프레임마다 이동 속도에 따른 좌표 보간을 적용해 느린 흔들림을 줄이고 빠른 움직임을 따라갑니다. 카메라는 최대 1280×960, 30fps를 요청하며 실제 지원 해상도를 사용합니다. 화면을 벗어나거나 탭이 숨겨지면 카메라 트랙과 Worker를 종료합니다. 늦게 도착하는 권한 허용도 이미 취소된 세션이면 즉시 정리합니다.

영상과 인식 좌표는 메모리에서만 처리하며 서버로 전송하지 않습니다. 마이크·녹화는 사용하지 않습니다. 사진은 촬영 버튼으로 메모리에 만들고, 별도의 저장 버튼으로 기기에 저장합니다. 사진 삭제·화면 전환 시 임시 URL을 해제합니다. 카메라를 켜기 전 움직이는 그림은 **미리보기용 일러스트**입니다.

의상과 소품은 실사 질감의 투명 PNG를 Canvas로 합성합니다. 내장 `image_gen`으로 생성한 금속·보석 왕관, 털 토끼 귀, 반사 렌즈 안경, 자수 한복, 메시 유니폼을 `public/camera/artwork/`에 저장했습니다. 원본 알파를 보존하며 생성 프롬프트와 파일 목록은 같은 폴더의 `manifest.json`에 있습니다. 추가 API 요청이나 영상 업로드 없이 로컬 에셋으로 표시합니다.

공룡·로봇은 투명한 얼굴 구멍이 있는 후드·헬멧으로 머리 크기와 회전에 맞춰집니다. 공주는 얼굴과 몸을 한 Worker 프레임에서 함께 인식해 왕관과 드레스를 각자 맞춥니다. 얼굴이나 몸 중 하나만 보일 때도 감지한 부분은 미리 보여 주지만, 두 부분이 함께 잡혀야 사진을 찍을 수 있습니다. 공주 퍼프 소매는 어깨와 팔을 따라 움직입니다. 새 3종의 이미지와 프롬프트는 `artwork/characters-manifest.json`에 기록했습니다.

한복은 어깨·팔꿈치·손목을 따라 움직이는 소매와 몸통 텍스처를 조합하고, 저고리와 치마의 가로 비율을 각각 조정합니다. 얼굴 소품은 눈·이마 좌표의 크기와 기울기를 따르고 고개 좌우 회전에 따라 투영 형태를 보정합니다. 85~120% 크기 조절을 지원합니다. 실제 3D 피팅, 몸의 깊이 변화에 따른 가림, 실제 옷을 지우는 생성형 교체는 구현하지 않았습니다. 인식을 놓치면 효과를 숨기고 자세 안내를 보여줍니다.

인식 파일은 `public/camera/`에서 같은 출처로 제공합니다. `@mediapipe/tasks-vision` 버전 1.0.1과 모델 버전 1을 고정했습니다. 파일을 복구하거나 라이브러리를 갱신할 때:

```bash
npm run prepare-camera
```

빌드 후 `node scripts/check-camera-browser.mjs`를 실행하고 `/camera-check.html`을 열면 실제 카메라 없이 기존 선수 사진으로 얼굴 478개·몸 33개 좌표 추론, 8종 에셋 로딩, 얼굴 효과 5종 및 공주의 얼굴·몸 동시 인식을 확인할 수 있습니다. 이 검사용 페이지는 제품 빌드에 포함되지 않고 다음 빌드에서 제거됩니다.

## 검증
```bash
npm run typecheck
npm test
npm run build
```
자동 검사는 음성 취소/녹음 폴백, 수학 문제 범위/보기/난이도 전환, 기록 복구/중복 완료 방지, 복습 선택 및 한글 획 데이터를 검증합니다. 실제 iPad Safari의 음성 품질·자동 재생 및 손가락 사용감은 기기에서 별도 확인이 필요합니다.

- 선수 ID는 기존 기록과 사진을 유지하며, 별도 선수 도감에서 실제 사진과 이름을 보여줍니다.

### 그림(AI 생성 이미지)
모든 단어는 이미 `/images/<id>.png` 를 바라보도록 배선돼 있다.
파일이 **없으면 이모지로 자동 폴백**, 채워 넣으면 그때부터 그림이 보인다(코드 수정 불필요).

```bash
OPENAI_API_KEY=sk-... npm run gen-images
```
- `data/words.json` 의 단어를 **고정 스타일 프롬프트**(아래)로 일괄 생성해
  `public/images/<id>.png` 로 저장. 이미 있는 파일은 건너뜀(이어받기 가능).
- 기본은 OpenAI Images(gpt-image-1). 다른 API는 `scripts/gen-images.mjs` 의 `callImageApi()` 만 교체.
- ⚠️ 비용 주의: 이미지 생성은 API 요금이 발생하므로 실행 전 생성할 단어 수를 확인하세요.

고정 스타일:
```
A single {english word}, cute flat illustration for a children's app,
soft rounded shapes, bright pastel colors, thick outlines,
centered on a plain off-white background, no text, no shadow.
```

### 축구선수 사진 (실제 인물)
새 선수 도감의 사진은 `scripts/fetch-player-photos.mjs`로 Wikimedia Commons에서 가져옵니다. 라이선스가 확인된 사진만 저장하며, 요청 제한에 따라 대기하고 이미 저장한 사진은 건너뜁니다.
```bash
node scripts/fetch-player-photos.mjs
```
사진은 `public/images/players/`, 저자·라이선스·원본 링크는 `data/photo-credits.json`에 저장합니다. 각 선수 카드와 부모 화면에서 출처를 확인할 수 있습니다. 현재 소속팀과 등번호는 변경될 수 있어 선수 카드에 고정하지 않습니다.

기존 사진 스크립트:

`scripts/fetch-photos.mjs` 가 위키피디아/위키미디어 공용에서 사진을 받아 `public/images/<id>.png` 로 저장:
```bash
node scripts/fetch-photos.mjs
```
- 선수(사카·홀란드·야말): 위키피디아 인포박스 사진(대개 CC 라이선스). 받은 뒤 `sips -Z 800 *.png` 로 다운스케일 권장.
- 구단(아스날·리버풀): 엠블럼은 **상표/비자유** — 개인용으로만. 배포 시 제외 필요.
- ⚠️ 나무위키 사진은 대부분 저작권 있는 보도사진이라 사용하지 않음.

### 아빠 목소리 녹음 끼워넣기 (나중에)
1. 단어를 또박또박 녹음해 `public/audio/ko/<id>.mp3`, `public/audio/en/<id>.mp3` 로 저장.
2. 해당 단어에 `audioKo: "/audio/ko/apple.mp3"`, `audioEn: "/audio/en/apple.mp3"` 추가.
   → 녹음이 있으면 TTS 대신 자동으로 녹음이 재생된다. (없으면 브라우저 TTS 폴백)

## 음성에 대해
학습 음성은 미리 만든 **로컬 MP3**를 우선 사용하며, 동적인 이름과 미등록 문장은 브라우저 **Web Speech API(TTS)**로 보완합니다. 브라우저 TTS 지원과 이름 발음은 기기/앱에 따라 다릅니다.
영어는 단어·악기 이름·생활영어·듣기 퀴즈 모두 **영국식 영어(en-GB)**를 사용합니다. macOS Daniel 음성을 분당 165단어로 생성하고 음량을 -18 LUFS / -2 dBTP로 맞춥니다. `npm run prepare-speech`로 다시 만들며, 음성·속도·처리 설정이 파일 주소에 반영돼 이전 캐시와 섞이지 않습니다. `public/audio/generated/british-voice.json`에 생성 설정과 각 MP3의 SHA-256을 기록합니다. 기존 페이지 캐시를 위해 이전 음성 파일은 유지합니다.
동적인 문장은 `en-GB` 기기 음성이 있을 때만 읽습니다. 음성 목록이 늦게 준비되면 최대 1.5초 기다리고, 영국식 음성이 없으면 안내를 표시합니다. 미국식 등 다른 영어 음성으로 자동 변경하지 않습니다. 이름을 제외한 준비된 학습 영어는 기기 TTS 없이도 재생됩니다.
`aeroplane`, `lorry`, `fire engine`, `sweet`, `ladybird` 등 영국식 표현을 사용하며, 기존 단어 ID는 유지해 학습 기록을 보존합니다. 참고: [Cambridge 어린이 영어 어휘](https://www.cambridgeenglish.org/Images/245852-yle-flyers-word-list-picture-book.pdf).
아이가 잘 붙으면 위 방식으로 **아빠 목소리 녹음**으로 업그레이드 권장.

### 동요 가사

음악방의 4곡에 한국어·영어 가사를 표시합니다. 함께 보기 / 한국어 / English를 선택하고, 전체 가사를 펼쳐 원하는 줄로 이동할 수 있습니다. 현재 줄은 `data/songs.json`의 BPM과 `data/song-lyrics.json`의 박자 구간을 사용해 합주 재생 위치를 따라갑니다. 일시정지·구간 이동·반복에도 같은 재생 시계를 사용합니다. 가사 표시 기능이며 별도 노래 보컬을 합성하지 않습니다.

한국어는 기존 한국어 번안 가사를 전재하지 않고, 이 앱을 위해 각 선율에 맞춰 새로 작성했습니다. 비행기·나비야 영어도 동일한 주제로 새로 작성했습니다. 작은 별 영어는 Jane Taylor의 퍼블릭 도메인 시 「The Star」 첫 연을 노래에 맞게 반복하며, 런던 다리 영어는 전래 동요의 첫 절입니다. 새 가사/전래 가사를 UI에 표시하고 전체 가사 아래 출처를 연결합니다. 한국어와 영어는 각각 부르기 위한 가사로, 문장별 직역은 아닙니다.

출처 확인: [The Star — Academy of American Poets](https://poets.org/poem/star/print), [London Bridge — BBC School Radio](https://teach.files.bbci.co.uk/schoolradio/london_bridge.pdf). 한국어 「비행기」의 기존 가사는 윤석중 작사로, 국립국어원의 「재외동포 아동용 한국어 교육 자료 개발 연구」(2017) 동요 목록에도 저작권이 명시돼 있어 수록하지 않았습니다.
